YumeBox 的 APK 由 Android/Kotlin 代码、mihomo Go 内核、Rust 配置编译器和两组 C 原生库组成。仅运行 Gradle 不会自动生成缺失的 `jniLibs`，首次构建需要先完成原生构建。

<Columns cols={2}>
  <Card title="构建问题" icon="circle-question-mark" href="/guide/faq" horizontal>
    根据构建输出或内核错误定位原因。
  </Card>

  <Card title="mihomo 配置" icon="file-code" href="https://wiki.metacubex.one/config/" horizontal>
    查看内核支持的配置字段。
  </Card>
</Columns>

<Tip>
  构建脚本会替换 `lib/mihomo/mihomo` 下现有的内核源码。不要在该目录保存未提交修改。
</Tip>

## 环境要求

以下版本来自当前仓库的 `gradle.properties` 与 GitHub Actions。使用其他版本可能可以构建，但不属于项目持续验证的组合。

<ResponseField name="OpenJDK" type="24" required>
  Gradle 与 Android 编译工具链使用 Java 24。CI 使用 Temurin 24。
</ResponseField>

<ResponseField name="Android SDK" type="API 37" required>
  `compileSdk` 和 `targetSdk` 均为 37，最低系统版本为 Android 8.0（API 26）。
</ResponseField>

<ResponseField name="Android NDK" type="30.0.14904198" required>
  Go 共享核心、Rust 和 C 原生库共用此 NDK。
</ResponseField>

<ResponseField name="CMake" type="3.22.1" required>
  用于构建 `libloader.so` 与 `libcompat.so`。脚本优先选择 3.22.1。
</ResponseField>

<ResponseField name="Kotlin CLI" type="2.x" required>
  用于执行 `scripts/native-build.main.kts`。Gradle Wrapper 不能替代 `kotlin` 命令。
</ResponseField>

<ResponseField name="Go" type="1.26" required>
  构建 mihomo 共享核心和 PIE 启动壳。项目 CI 使用 MetaCubeX 的 Go 1.26 构建。
</ResponseField>

<ResponseField name="Rust" type="nightly" required>
  需要 `rust-src`、四个 Android target 和 `cargo-ndk`。
</ResponseField>

<ResponseField name="Git / patch" type="command line" required>
  `sync-kernel.sh` 使用 Git 拉取内核；Go Android 兼容补丁需要 GNU `patch`。
</ResponseField>

<Info>
  Windows 建议安装 Git for Windows，并在 Git Bash 中执行 `.sh` 与 `patch` 命令。Gradle 和 Kotlin 命令可以在 PowerShell 中执行。
</Info>

## 准备项目

<Steps>
  <Step title="克隆仓库">
    项目不使用 Git submodule，mihomo 源码会在后续步骤单独同步。

    ```bash 克隆仓库
    git clone https://github.com/YumeYucca/YumeBox.git
    cd YumeBox
    ```
  </Step>

  <Step title="安装 Android 组件">
    确保 Android SDK Command-line Tools 的 `bin` 目录已加入 `PATH`。

    <CodeGroup>
      ```bash Linux / macOS / Git Bash
      sdkmanager "platforms;android-37" "ndk;30.0.14904198" "cmake;3.22.1"
      ```

      ```powershell PowerShell
      sdkmanager "platforms;android-37" "ndk;30.0.14904198" "cmake;3.22.1"
      ```
    </CodeGroup>
  </Step>

  <Step title="配置 Android SDK 路径">
    在仓库根目录创建 `local.properties`。使用正斜杠可以避免 Windows 路径转义问题。

    <CodeGroup>
      ```properties Linux / macOS
      sdk.dir=/home/yume/Android/Sdk
      ```

      ```properties Windows
      sdk.dir=C:/Users/Yume/AppData/Local/Android/Sdk
      ```
    </CodeGroup>

    `ndk.dir` 通常不需要配置，脚本会读取 `android.ndkVersion` 并定位 SDK 下对应目录。
  </Step>

  <Step title="同步 mihomo 内核">
    在 Linux、macOS 或 Git Bash 中选择一个内核通道：

    ```bash 同步 Alpha 内核
    ./scripts/sync-kernel.sh alpha
    ```

    <Tabs sync={false}>
      <Tab title="alpha">
        MetaCubeX `Alpha` 分支，项目默认通道。
      </Tab>

      <Tab title="meta">
        MetaCubeX `Meta` 分支。
      </Tab>

      <Tab title="smart">
        vernesong/mihomo 的 `Alpha` 分支，构建版本会带 `-Smart` 后缀。
      </Tab>
    </Tabs>
  </Step>

  <Step title="应用 Go Android 补丁">
    这些补丁与 CI 保持一致，用于禁用 Android 上不兼容的 `pidfd`，并修正 32 位目标的 time64 syscall。补丁会修改当前 Go SDK，建议使用专门用于 YumeBox 的可写 Go 安装。

    ```bash 应用或识别已应用的补丁
    project_root="$PWD"
    cd "$(go env GOROOT)"

    for patch_file in "$project_root"/.github/patch/*.patch; do
      if patch --forward --dry-run -p 1 < "$patch_file" >/dev/null 2>&1; then
        patch --forward -p 1 < "$patch_file"
      elif patch --reverse --dry-run -p 1 < "$patch_file" >/dev/null 2>&1; then
        echo "Already applied: $patch_file"
      else
        echo "Cannot apply: $patch_file" >&2
        exit 1
      fi
    done

    cd "$project_root"
    ```
  </Step>

  <Step title="准备 Rust Android target">
    ```bash 安装 Rust 工具链
    rustup toolchain install nightly --component rust-src
    rustup target add --toolchain nightly \
      armv7-linux-androideabi \
      aarch64-linux-android \
      i686-linux-android \
      x86_64-linux-android
    cargo install cargo-ndk
    ```
  </Step>
</Steps>

## 构建原生组件

首次构建或内核、Rust、C 源码发生变化后，执行原生构建脚本：

<Tabs>
  <Tab title="完整构建">
    构建四种 ABI 的内核与原生库，并下载 Geo 数据。

    ```bash 完整原生构建
    kotlin scripts/native-build.main.kts --all
    ```
  </Tab>

  <Tab title="仅 arm64-v8a">
    适合本机调试，减少 Go、Rust 和 C 的重复编译。

    <CodeGroup>
      ```bash Linux / macOS / Git Bash
      ABI_APP_LIST=arm64-v8a kotlin scripts/native-build.main.kts --go --rust --compat --loader
      ```

      ```powershell PowerShell
      $env:ABI_APP_LIST = "arm64-v8a"
      kotlin scripts/native-build.main.kts --go --rust --compat --loader
      ```
    </CodeGroup>
  </Tab>
</Tabs>

### 可单独执行的任务

<ResponseField name="--go" type="native">
  构建 mihomo 共享核心 `libmihomocore.so` 和 PIE 启动壳 `libmihomo.so`。
</ResponseField>

<ResponseField name="--rust" type="native">
  构建 Rust 配置编译器，输出 `liboverride.so`。
</ResponseField>

<ResponseField name="--compat" type="native">
  构建进程与 Unix socket bridge，输出 `libcompat.so`。
</ResponseField>

<ResponseField name="--loader" type="native">
  构建 APK payload loader，输出 `libloader.so`。
</ResponseField>

<ResponseField name="--geo" type="assets">
  下载并压缩 GeoIP、GeoSite、ASN 和 BundleMRS 数据。
</ResponseField>

<ResponseField name="--clean" type="maintenance">
  清理脚本产生的 native、Geo 和版本标记文件。
</ResponseField>

<Check>
  成功后，每个目标 ABI 的 `jniLibs/&lt;abi&gt;/` 下应包含 `libmihomo.so`、`libmihomocore.so`、`liboverride.so`、`libcompat.so`、`libloader.so` 和 `core-version.properties`。
</Check>

## 构建 APK

<CodeGroup>
  ```bash Linux / macOS
  # 默认：arm64-v8a、外置 Geo 数据
  ./gradlew :app:assembleDebug

  # arm64-v8a、内置 Geo 数据
  ./gradlew -Pgeo.bundle=true :app:assembleDebug

  # 全 ABI、内置 Geo 数据
  ./gradlew -Pbuild.allAbis=true -Pgeo.bundle=true :app:assembleRelease
  ```

  ```powershell Windows
  # 默认：arm64-v8a、外置 Geo 数据
  .\gradlew.bat :app:assembleDebug

  # arm64-v8a、内置 Geo 数据
  .\gradlew.bat -Pgeo.bundle=true :app:assembleDebug

  # 全 ABI、内置 Geo 数据
  .\gradlew.bat -Pbuild.allAbis=true -Pgeo.bundle=true :app:assembleRelease
  ```
</CodeGroup>

<Columns cols={2}>
  <Card title="external" icon="cloud-download">
    APK 不携带 Geo 数据，体积较小；首次使用时需要网络下载。
  </Card>

  <Card title="builtin" icon="package-check">
    APK 携带 Geo 数据，安装后可直接使用，但文件更大。
  </Card>
</Columns>

APK 输出目录为 `app/build/outputs/apk/debug/` 或 `app/build/outputs/apk/release/`。默认本地构建只生成 `arm64-v8a`；`-Pbuild.allAbis=true` 会生成各 ABI 拆分包和 universal APK。

## Release 签名

没有签名配置时仍可执行本地编译，但正式分发应使用独立密钥。在仓库根目录放置 `release.keystore`，并创建 `signing.properties`：

```properties signing.properties
keystore.password=your-store-password
key.alias=yumebox
key.password=your-key-password
```

<ParamField body="keystore.password" type="string" required>
  `release.keystore` 的 store password。
</ParamField>

<ParamField body="key.alias" type="string" required>
  用于签名的 key alias。
</ParamField>

<ParamField body="key.password" type="string" required>
  对应 key 的 password。
</ParamField>

<Danger>
  不要提交 `release.keystore` 或 `signing.properties`。仓库已忽略这些文件，但仍应在提交前检查 `git status`。
</Danger>

## 验证构建

<Steps>
  <Step title="编译 Kotlin 与资源">
    <CodeGroup>
      ```bash Linux / macOS
      ./gradlew :app:compileDebugKotlin
      ```

      ```powershell Windows
      .\gradlew.bat :app:compileDebugKotlin
      ```
    </CodeGroup>
  </Step>

  <Step title="确认 APK 产物">
    检查 `app/build/outputs/apk/` 下的文件名、ABI 与 Geo 类型是否符合预期。
  </Step>

  <Step title="安装到目标设备">
    ```bash 安装 Debug APK
    adb install -r app/build/outputs/apk/debug/YumeBox-external.apk
    ```

    实际文件名由当前版本和构建参数决定；命令执行前先查看输出目录。
  </Step>
</Steps>
