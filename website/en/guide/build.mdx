The FlyCat APK consists of Android/Kotlin code, the mihomo Go core, and Rust native libraries (configuration compiler and payload extractor). Running Gradle alone does not generate missing `jniLibs`; complete the native build before your first APK build.

<Tip>
  The build script replaces the existing core source under `lib/mihomo/mihomo`. Do not keep uncommitted changes in that directory.
</Tip>

## Requirements

These versions come from the current repository's `gradle.properties` and GitHub Actions workflows. Other versions may work, but they are not part of the combination continuously verified by the project.

<ResponseField name="OpenJDK" type="24" required>
  Gradle and the Android build toolchain use Java 24. CI uses Temurin 24.
</ResponseField>

<ResponseField name="Android SDK" type="API 37" required>
  Both `compileSdk` and `targetSdk` are 37. The minimum system version is Android 8.0 (API 26).
</ResponseField>

<ResponseField name="Android NDK" type="30.0.14904198" required>
  The Go shared core, Rust, and C native libraries use this NDK.
</ResponseField>

<ResponseField name="CMake" type="3.22.1" required>
  Used for C/CMake native library builds. The script prefers version 3.22.1.
</ResponseField>

<ResponseField name="Kotlin CLI" type="2.x" required>
  Used to run `scripts/native-build.main.kts`. The Gradle Wrapper cannot replace the `kotlin` command.
</ResponseField>

<ResponseField name="Go" type="1.26" required>
  Builds the mihomo shared core and PIE launcher. Project CI uses MetaCubeX Go 1.26.
</ResponseField>

<ResponseField name="Rust" type="nightly" required>
  Requires `rust-src`, four Android targets, and `cargo-ndk`.
</ResponseField>

<ResponseField name="Git / patch" type="command line" required>
  `sync-kernel.sh` uses Git to fetch the core, and the Go Android compatibility patches require GNU `patch`.
</ResponseField>

<Info>
  On Windows, install Git for Windows and run `.sh` and `patch` commands in Git Bash. You can run Gradle and Kotlin commands in PowerShell.
</Info>

## Prepare the project

<Steps>
  <Step title="Clone the repository">
    The project does not use Git submodules. You will sync the mihomo source separately in a later step.

    ```bash Clone the repository
    git clone https://github.com/LM-Firefly/FlyCat.git
    cd FlyCat
    ```
  </Step>

  <Step title="Install Android components">
    Make sure the Android SDK Command-line Tools `bin` directory is in `PATH`.

    <CodeGroup>
      ```bash Linux / macOS / Git Bash
      sdkmanager "platforms;android-37" "ndk;30.0.14904198" "cmake;3.22.1"
      ```

      ```powershell PowerShell
      sdkmanager "platforms;android-37" "ndk;30.0.14904198" "cmake;3.22.1"
      ```
    </CodeGroup>
  </Step>

  <Step title="Configure the Android SDK path">
    Create `local.properties` in the repository root. Forward slashes avoid Windows path-escaping problems.

    <CodeGroup>
      ```properties Linux / macOS
      sdk.dir=/home/yume/Android/Sdk
      ```

      ```properties Windows
      sdk.dir=C:/Users/Yume/AppData/Local/Android/Sdk
      ```
    </CodeGroup>

    You normally do not need to set `ndk.dir`. The script reads `android.ndkVersion` and locates the matching directory under the SDK.
  </Step>

  <Step title="Sync the mihomo core">
    Select a core channel in Linux, macOS, or Git Bash:

    ```bash Sync the Alpha core
    ./scripts/sync-kernel.sh alpha
    ```

    <Tabs sync={false}>
      <Tab title="alpha">
        The MetaCubeX `Alpha` branch and the project's default channel.
      </Tab>

      <Tab title="smart">
        The vernesong `Smart` branch.
      </Tab>

      <Tab title="meta">
        The MetaCubeX `Meta` branch.
      </Tab>

    </Tabs>
  </Step>

  <Step title="Apply the Go Android patches">
    These patches match CI. They disable Android-incompatible `pidfd` support and fix time64 syscalls for 32-bit targets. The patches modify the current Go SDK, so use a writable Go installation dedicated to FlyCat.

    ```bash Apply the patches or detect existing patches
    project_root="$PWD"
    cd "$(go env GOROOT)"

    for patch_file in "$project_root"/.github/patch/*.patch; do
      if patch --forward --dry-run -p 1 < "$patch_file" >/dev/null 2>&1; then
        patch --forward -p 1 < "$patch_file"
      elif patch --reverse --dry-run -p 1 < "$patch_file" >/dev/null 2>&1; then
        echo "Already applied: $patch_file"
      else
        echo "Cannot apply: $patch_file" >&2
        exit 1
      fi
    done

    cd "$project_root"
    ```
  </Step>

  <Step title="Prepare Rust Android targets">
    ```bash Install the Rust toolchain
    rustup toolchain install nightly --component rust-src
    rustup target add --toolchain nightly \
      armv7-linux-androideabi \
      aarch64-linux-android \
      i686-linux-android \
      x86_64-linux-android
    cargo install cargo-ndk
    ```
  </Step>
</Steps>

## Build native components

Run the native build script for the first build and whenever the core, Rust, or C source changes:

<Tabs>
  <Tab title="Full build">
    Build the core and native libraries for all four ABIs and download Geo data.

    ```bash Full native build
    kotlin scripts/native-build.main.kts --all
    ```
  </Tab>

  <Tab title="arm64-v8a only">
    Use this for local debugging to avoid repeating Go, Rust, and C compilation for other ABIs.

    <CodeGroup>
      ```bash Linux / macOS / Git Bash
      ABI_APP_LIST=arm64-v8a kotlin scripts/native-build.main.kts --go --rust --loader
      ```

      ```powershell PowerShell
      $env:ABI_APP_LIST = "arm64-v8a"
      kotlin scripts/native-build.main.kts --go --rust --loader
      ```
    </CodeGroup>
  </Tab>
</Tabs>

### Individual tasks

<ResponseField name="--go" type="native">
  Build the mihomo shared core `libmihomo.so`.
</ResponseField>

<ResponseField name="--rust" type="native">
  Build the Rust configuration compiler and output `liboverride.so`.
</ResponseField>

<ResponseField name="--loader" type="native">
  Build the APK payload loader and output `libloader.so`.
</ResponseField>

<ResponseField name="--geo" type="assets">
  Download and compress GeoIP, GeoSite, ASN, and BundleMRS data.
</ResponseField>

<ResponseField name="--clean" type="maintenance">
  Remove native, Geo, and version-marker files generated by the script.
</ResponseField>

<Check>
  After a successful build, `jniLibs/&lt;abi&gt;/` for every target ABI should contain `libmihomo.so`, `liboverride.so`, `libloader.so`, and `core-version.properties`.
</Check>

## Build the APK

<CodeGroup>
  ```bash Linux / macOS
  # Default: arm64-v8a with external Geo data
  ./gradlew :app:assembleDebug

  # arm64-v8a with built-in Geo data
  ./gradlew -Pgeo.bundle=true :app:assembleDebug

  # All ABIs with built-in Geo data
  ./gradlew -Pgeo.bundle=true :app:assembleRelease
  ```

  ```powershell Windows
  # Default: arm64-v8a with external Geo data
  .\gradlew.bat :app:assembleDebug

  # arm64-v8a with built-in Geo data
  .\gradlew.bat -Pgeo.bundle=true :app:assembleDebug

  # All ABIs with built-in Geo data
  .\gradlew.bat -Pgeo.bundle=true :app:assembleRelease
  ```
</CodeGroup>

<Columns cols={2}>
  <Card title="external" icon="cloud-download">
    The APK does not contain Geo data and is smaller. The first use requires a network download.
  </Card>

  <Card title="builtin" icon="package-check">
    The APK contains Geo data and works immediately after installation, but the file is larger.
  </Card>
</Columns>

APK output is written to `app/build/outputs/apk/debug/` or `app/build/outputs/apk/release/`. `assembleDebug` defaults to `arm64-v8a` only; `assembleRelease` builds a Universal APK containing all four ABIs.

## Release signing

You can compile locally without signing configuration, but production distribution should use a dedicated key. Place `release.keystore` in the repository root and create `signing.properties`:

```properties signing.properties
keystore.password=your-store-password
key.alias=flycat
key.password=your-key-password
```

<ParamField body="keystore.password" type="string" required>
  The store password for `release.keystore`.
</ParamField>

<ParamField body="key.alias" type="string" required>
  The alias of the key used for signing.
</ParamField>

<ParamField body="key.password" type="string" required>
  The password for that key.
</ParamField>

<Danger>
  Do not commit `release.keystore` or `signing.properties`. The repository ignores these files, but you should still check `git status` before committing.
</Danger>

## Verify the build

<Steps>
  <Step title="Compile Kotlin and resources">
    <CodeGroup>
      ```bash Linux / macOS
      ./gradlew :app:compileDebugKotlin
      ```

      ```powershell Windows
      .\gradlew.bat :app:compileDebugKotlin
      ```
    </CodeGroup>
  </Step>

  <Step title="Confirm the APK output">
    Check the filename, ABI, and Geo type under `app/build/outputs/apk/`.
  </Step>

  <Step title="Install on the target device">
    ```bash Install the Debug APK
    adb install -r app/build/outputs/apk/debug/FlyCat-external.apk
    ```

    The exact filename depends on the current version and build parameters. Check the output directory before running the command.
  </Step>
</Steps>
