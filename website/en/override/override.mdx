Overrides layer local configuration onto a subscription before mihomo loads it. They never edit the source subscription. Every start or reload applies bound overrides in order and then compiles the effective profile.

## When to use them

- Add fixed DNS, logging, or rules to a subscription.
- Replace one proxy group or a small hosts map.
- Generate a patch from profile content with JavaScript.
- Import reusable override files from local storage or a URL.

## Create and bind an override

<Steps>
  <Step title="Create or import">
    In Overrides, create YAML or JavaScript, or import a local file or network URL. The extension decides the type: `.yaml`, `.yml`, or `.js`.
  </Step>
  <Step title="Write the patch">
    Use YAML for fixed fields. Use JavaScript for conditional logic.
  </Step>
  <Step title="Bind it to a profile">
    Add the override in the target profile's override settings and arrange the order. Each later override receives the result of the prior one.
  </Step>
  <Step title="Restart the proxy">
    Overrides apply during configuration compilation. Restart or reload the proxy and check logs after saving.
  </Step>
</Steps>

## YAML example

This keeps the subscription's rules and appends one local rule:

```yaml
dns:
  enable: true
  nameserver:
    - https://dns.alidns.com/dns-query

rules-end:
  - DOMAIN-SUFFIX,example.com,DIRECT
```

Objects merge recursively. A plain list replaces the existing list; use `-start` or `-end` when retaining it. See [override syntax](/override/fields) for the full rules.

## JavaScript example

JavaScript must define `main(profile)` and return a configuration object. JS uses `rules+` to append a list; YAML's `rules-end` is not JS syntax.

```js
function main(profile) {
  return deepMerge(profile, {
    "rules+": ["DOMAIN-SUFFIX,example.com,DIRECT"],
  }, true);
}
```

<Warning>When **Disable all overrides** is enabled in Root TUN or transparent proxy mode, user overrides and runtime patches do not run.</Warning>
