覆写是在订阅配置加载前叠加的一层本机配置。它不会修改订阅源文件；每次启动或重载时，YumeBox 按绑定顺序把覆写应用到当前配置，再交给 mihomo。

## 什么时候用

- 给所有订阅补充固定 DNS、日志级别或规则。
- 只替换一个策略组或一段 hosts。
- 用 JavaScript 根据配置内容生成补丁。
- 从本地文件或 URL 导入可复用的覆写文件。

## 创建和绑定

<Steps>
  <Step title="创建或导入">
    在“覆写”页面新建 YAML/JavaScript，或从本地文件、网络 URL 导入。扩展名决定类型：`.yaml`、`.yml` 或 `.js`。
  </Step>
  <Step title="编写内容">
    YAML 适合固定字段；需要条件逻辑时使用 JavaScript。
  </Step>
  <Step title="绑定到配置">
    在目标配置的覆写设置中添加文件，并调整顺序。后面的覆写基于前面的结果继续执行。
  </Step>
  <Step title="重启代理">
    覆写只在编译配置时生效。保存后重启或重载代理，再从日志确认结果。
  </Step>
</Steps>

## YAML 示例

下面的写法保留订阅的原有规则，并在最后追加一条本机规则：

```yaml
dns:
  enable: true
  nameserver:
    - https://dns.alidns.com/dns-query

rules-end:
  - DOMAIN-SUFFIX,example.com,DIRECT
```

对象字段会递归合并；普通列表会替换原列表。要在保留原列表的基础上插入项目，使用 `-start` 或 `-end`。完整规则见 [覆写语法](/override/fields)。

## JavaScript 示例

JavaScript 必须定义 `main(profile)` 并返回配置对象。JS 的列表追加语法是 `rules+`，不是 YAML 的 `rules-end`。

```js
function main(profile) {
  return deepMerge(profile, {
    "rules+": ["DOMAIN-SUFFIX,example.com,DIRECT"],
  }, true);
}
```

<Warning>Root TUN 和透明代理开启“禁用所有覆写”后，用户覆写和运行时补丁都不会执行。</Warning>
